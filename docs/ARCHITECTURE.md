# Архитектура «Сечения 3D»

## 1. Общая схема

```
┌──────────────────────────── UI (React) ─────────────────────────────┐
│ TopBar · LeftPanel · Viewport · RightPanel · SolutionPanel · Lessons │
└──────────────┬───────────────────────────────────────┬──────────────┘
               │ actions                               │ derived data (memo)
        ┌──────▼──────┐                       ┌────────▼─────────┐
        │ state/store │── problem (kind,      │ state/derive.ts  │
        │  (zustand)  │   params, points) ───►│ poly → plane →   │
        └──────┬──────┘                       │ section → checks │
               │ props                        │ → construction   │
        ┌──────▼─────────────┐                └────────▲─────────┘
        │ scene/SceneController│  (Three.js, императивно)  │
        │ picking (raycast)   │────── pick events ────────┘
        └─────────────────────┘
                                   ┌──────────── core (чистый TS, без DOM) ───────────┐
                                   │ geometry · polyhedra · section · validation ·    │
                                   │ construction · problem · exercises               │
                                   └──────────────────────────────────────────────────┘
```

**Единственный источник истины** — `Problem` в store: тип многогранника, его параметры
и список заданных точек (`PointSpec`). Всё остальное (многогранник, плоскость, сечение,
проверки, школьное решение) — производные данные, вычисляемые чистыми функциями ядра и
мемоизируемые по входам. Сцена ничего не вычисляет: она только рисует то, что дало ядро.

## 2. Модули

| Модуль | Ответственность |
|---|---|
| `core/geometry` | `Vec3`, операции над векторами, плоскость, знаковое расстояние, пересечения отрезок–плоскость и прямая–прямая, 2D-оболочка, допуски (`Tolerance`) |
| `core/polyhedra` | Единая модель `Polyhedron` (vertices, labels, faces, edges, facePlanes, adjacency, parallel faces с обоснованием), фабрики: призма, пирамида, куб, параллелепипед, тетраэдр, платоновы тела; проверка корректности модели |
| `core/section` | `PointSpec` → координаты; плоскость по трём точкам с диагностикой вырожденности; алгоритм сечения; подписи точек |
| `core/validation` | Независимые проверки результата сечения (в том числе альтернативным алгоритмом через выпуклую оболочку) |
| `core/construction` | Генерация школьного решения (метод следов, параллельность граней, внутреннее проектирование, координатный метод как честный запасной вариант) + проверка каждого шага |
| `core/problem` | Разбор школьной записи (`M ∈ AB, AM:MB = 2:1`), обратное форматирование, сериализация в URL/файл, генератор задач, примеры |
| `core/exercises` | Проверка ответа ученика (отмеченные вершины сечения, тип многоугольника) с объяснением ошибок |
| `scene` | `SceneController` на Three.js: геометрия, линии (Line2), подписи (CSS2D), камера, виды, выбор точек (raycasting + экранная привязка к вершинам/рёбрам), экспорт PNG, освобождение ресурсов |
| `state` | zustand-store, действия, производные вычисления |
| `lessons` | Данные 10 уроков: теория, модель, демонстрация, упражнение |
| `components` | React-компоненты интерфейса |

Почему не React Three Fiber: сцена небольшая, но требует точного контроля над порядком
отрисовки (скрытые рёбра пунктиром через `GreaterDepth`, сечение поверх граней), над
освобождением ресурсов и над пикингом с экранной привязкой. Императивный контроллер с
явным API (`setPolyhedron`, `setSection`, `setConstruction`, `setStep`) проще тестировать
и не пересоздаёт сцену при каждом изменении состояния.

## 3. Математическая модель многогранника

```ts
interface Polyhedron {
  kind: PolyhedronKind;
  vertices: Vec3[];          // координаты (z — вверх, школьная система)
  labels: string[];          // A, B, C, A₁ … ; S — вершина пирамиды
  faces: number[][];         // циклы индексов, обход против часовой стрелки снаружи
  edges: [number, number][]; // выводятся из граней, a < b
  edgeFaces: [number, number][]; // две грани каждого ребра
  facePlanes: Plane[];       // внешняя нормаль
  parallelFaces: { a, b, reason }[]; // пары параллельных граней + школьное обоснование
  scale: number;             // характерный размер (диагональ bbox)
}
```

Фабрики задают вершины и грани явно (призмы, пирамиды, параллелепипеды, тетраэдр) или через
выпуклую оболочку точек (октаэдр, додекаэдр, икосаэдр). Каждая модель проверяется
`validatePolyhedron`: ссылки, плоскостность граней, ориентация (каждое направленное ребро
встречается ровно один раз), выпуклость, формула Эйлера.

## 4. Алгоритм сечения (кратко; подробно — `MATHEMATICS.md`)

1. Плоскость по трём точкам: нормаль `n = (P2−P1)×(P3−P1)`, проверка совпадения и
   коллинеарности по относительному синусу угла.
2. Знаковые расстояния вершин → классы `+ / − / 0` с допуском `ε = 1e-9·L`.
3. Если нет вершин по обе стороны — касание: пусто / точка / ребро / грань (выпуклая
   оболочка нулевых вершин).
4. Иначе для каждой грани — обход цикла и сбор точек: нулевые вершины и строгие
   пересечения рёбер `t = dA/(dA−dB)`. Каждая грань даёт ≤ 1 отрезок — сторону сечения.
5. Из отрезков строится граф, каждая вершина обязана иметь степень 2; обход даёт цикл.
   Ориентация согласуется с нормалью плоскости.
6. Независимая проверка (`validation`).

## 5. Численная погрешность

`Tolerance` создаётся из масштаба фигуры: `dist = 1e-9·L`, `merge = 1e-8·L`,
`param = 1e-9`, `collinearSin = 1e-6` (ошибка), `illConditionedSin = 1e-3` (предупреждение).
Классификация вершин делается **один раз**, и все дальнейшие решения (пересекает ли ребро,
нулевая ли вершина) опираются на эти классы — это исключает противоречия между гранями.

## 6. Вырожденные случаи

| Ситуация | Поведение |
|---|---|
| совпадающие / коллинеарные / почти коллинеарные точки | плоскость не строится, понятное сообщение |
| плоскость через вершину | вершина входит в сечение без дубликатов |
| ребро в плоскости | ребро — сторона сечения (или само пересечение, если касание) |
| плоскость = грань | результат `face`, явно помечен как вырожденный |
| касание в вершине / по ребру | результат `point` / `segment` |
| нет пересечения | `empty` |

## 7. Школьное решение

`buildConstruction(poly, section, definingPoints)` моделирует построение на бумаге.
Состояние: известные точки секущей плоскости (с множеством плоскостей граней, которым они
принадлежат), известные следы `α ∩ (грань)`. Правила с приоритетами:

* **A. Соединение** — две известные точки в плоскости грани ⇒ след (аксиома о прямой в плоскости).
* **B. Пересечение** — след в грани ∩ прямая ребра этой грани ⇒ вершина сечения или
  вспомогательная точка на продолжении ребра (она лежит в плоскости соседней грани).
* **C. Параллельные грани** — след в грани F, точка в параллельной грани G ⇒ след в G
  параллелен (теорема о пересечении параллельных плоскостей третьей). Используется только
  когда параллельность граней обоснована свойствами фигуры.
* **D. Внутреннее проектирование** — для призм (параллельно боковому ребру) и пирамид
  (центрально из вершины) на плоскость основания.
* **E. Координатный метод** — честный запасной вариант, если правила A–D не дают шаг.

Каждый шаг хранит: действие, обоснование, использованные точки/прямые/грани, добавленные
объекты. `verifyConstruction` перепроверяет численно каждое утверждение каждого шага.

## 8. Выбор точек

* На модели: луч камеры → пересечение с треугольниками граней (`raycast`), плюс экранная
  привязка к вершинам (≤ 14 px) и рёбрам (≤ 9 px). Для ребра параметр `t` считается как
  ближайшая точка между лучом и отрезком ребра в 3D; опционально привязка к «школьным» долям.
  Точка на грани хранится весами вершин грани (барицентрически), поэтому остаётся на грани
  при изменении размеров фигуры.
* Условиями: парсер школьной записи + структурная форма. Оба способа создают одинаковый
  `PointSpec`, поэтому точки редактируются любым способом.

## 9. Тестирование

* Vitest: примитивы, модели многогранников, сценарии сечений, вырожденные случаи,
  property-based (fast-check) — инварианты для случайных плоскостей и перестановок, проверка
  школьного решения на тысячах случайных задач.
* Playwright: реальные пользовательские сценарии в Chromium (WebGL через SwiftShader).

## 10. Структура файлов (итоговая)

```
src/
  core/                      ← чистый TypeScript, без DOM
    geometry/  vec.ts plane.ts hull2d.ts tolerance.ts
    polyhedra/ types.ts build.ts catalog.ts validate.ts
    section/   points.ts computeSection.ts labels.ts
    validation/validateSection.ts
    construction/ types.ts buildConstruction.ts
    problem/   parse.ts serialize.ts examples.ts
    exercises/ check.ts
    solve.ts                 ← конвейер: точки → плоскость → сечение → проверки → решение
  scene/       SceneController.ts picking.ts coords.ts
  state/       store.ts (zustand) derived.ts (мемоизация производных)
  lessons/     lessons.ts toProblem.ts
  components/  TopBar LeftPanel Viewport RightPanel SolutionPanel LessonPanel Misc icons
tests/unit/    Vitest + fast-check
tests/e2e/     Playwright
```

Отличия от первоначального плана, появившиеся при реализации:

* **Правило F — параллельность прямой и плоскости.** Если след AB в грани отсекает на
  сторонах угла O пропорциональные отрезки, то AB ∥ PQ (подобие треугольников); любое ребро,
  параллельное PQ (с цепочкой школьных обоснований из `parallelEdges`), параллельно α, и след
  α в грани, содержащей это ребро, ему параллелен. Без этого правила типичные задачи вроде
  «SM : SA = SN : SB» приходилось бы решать координатно.
* **Согласование допусков.** Если точка пересечения ребра оказалась бы ближе допуска слияния к
  вершине, вершина считается лежащей в плоскости. Найдено property-based тестом: без этого
  возникали ложные «микро-стороны» длиной ~1e-8·L.
* Многогранник центрируется на сцене по габаритам, а не по центроиду вершин.
